## 证据分类与尺寸优先级

- C / Confirmed from drawing：图中标注或可辨认关系，不代表标注自洽。
- D / Derived：由选定数据计算。
- A / Assumed：待人工核对的灰盒参数。
- 优先顺序：空间关系和主入口/主要墙洞位置 → 标称9.6×7.5m参考框 → 明确记录的局部近似。
- 保留厨房左上、卫生间左中、次卧左下、入口下中、客厅中央、餐区上中、主卧右下、阳台右上的关系。
- 没有在通路检测后扩大洞口、挪动墙体或缩小家具；此阶段没有家具。
- 不将图像当作严格等比例施工图：X/Z方向分别按标称参考范围近似落位，细部有取整。
- 所有新的数值墙线、窗线、房间边界均为 A。图中总体关系为 C，面积计算为 D。
- 固定墙体是本灰盒基线下的固定元素；黑色图示本身不能证明承重性质。没有设置可移动墙体。

## 坐标与面积口径

- 1 Unity Unit = 1m；所有尺寸以米记录；Y向上。
- 主入口门洞中点为 (0,0,0)，图右 +X，图上 +Z；不是精确地理北向。
- 地板上表面 Y=0；厚0.10m、中心Y=-0.05m。
- ApartmentRoot及五个主分组保持位置0、旋转0、缩放1；各几何体 Inspector Scale 就是 Cube 实际尺寸。
- 结构外包范围 X=[-4.20,5.40]，Z=[-0.15,7.35]，即9.60×7.50m。
- 72㎡仅是标称外部参考框乘积；不是经过校核的净使用面积。
- 西南扩出、次卧/入口边界转折、底部入口和右下凸出均以分段几何近似；不是一个铺满72㎡的地板。
- 八区地面面积合计54.2650㎡，其中阳台5.2925㎡、室内48.9725㎡。这些是灰盒分区矩形并集，不含门洞阈值地板、不含墙体，不作为建筑事实。
- 六个门洞阈值地板另合计1.1000㎡，用于连接墙厚范围内的地面。所有地板模块互不发生正面积重叠。
- 实际建筑围合面积仍未核实，不强制各面积口径相等。

```
ApartmentRoot
├─ Structure           分段墙体、门楣、阈值地板、窗占位

├─ Furniture           空
```

## Unity Editor 打开、检查与安全再生成

1. 在现有项目的Unity 6000.6.4f1中等待正常导入/编译完成。助手本次未启动Editor或批处理导入。
2. 在Project中双击 `Assets/Scenes/ApartmentPhase2.unity`，单独打开新场景；旧场景若有未保存改动，先保留并取消切换，勿丢弃。
3. 在Hierarchy选ApartmentRoot并按F；Scene点击Y轴切俯视，检查八个房间的位置关系。
4. 展开Rooms，逐个选Floor检查Transform；地面上表面应为0、Collider为非Trigger。
5. 展开Structure，检查侧墙与Lintel；门洞内不能出现覆盖整个洞口的BoxCollider。
6. 可用Window > Analysis > Physics Debugger观察碰撞几何；不同Editor菜单显示可能略有差别。
7. 单独打开灰盒后运行 `Apartment Phase 2 > M1-A > Validate Active Graybox (Read Only)`。预期Console显示6 openings、7 route segments、failures=0；工具不保存资产。
8. 沿Anchors逐点检查，再将Scene视角降至眼高观察。M1-A不需要Play，也没有自主移动。
9. 如原生YAML无法加载或希望用Editor重新序列化，运行 `Apartment Phase 2 > M1-A > Create New Graybox Copy`。
   - 读取同一JSON数据与现有材质，使用GameObject.CreatePrimitive生成。
   - 目标已存在时保存到唯一的ApartmentPhase2_Copy*.unity；绝不覆盖ApartmentPhase2或旧场景。
   - Additive创建，不关闭或保存其他场景；恢复之前的活动场景，Console提示新副本路径。
   - 手动单独打开新副本后再验证。仅由你操作菜单时会新增副本及.meta。
   - 不更改Build Settings、XR设置、Packages或Oculus配置，不自动执行。
10. 如果Console有错误，保留错误文字和对象名，不先运行旧TwoRoomSceneBuilder，不自动升级包。
