## Safe teleport inspection

`SafeResetPoint` GO `1342695679`, Transform `1342695680`, is `(4.25,0,-1.55)`, inside Entrance. The entrance platform slab is centred `(4.25,-.3,-1.3)` with scale `(3.1,.6,2.6)` around a unit cube, so its top is Y=0. Rail positions are well outside the nominal radius-.30 landing footprint, but runtime occupied-space tests remain authoritative.

The existing UI path is **B -> Settings -> Return to Safe Position -> confirmation** (`ApartmentMenuController.ConfirmReset` -> `ApartmentVRLocomotion.TrySafetyReset`). B is not a direct teleport binding. Ordinary A hold/release teleport remains separate. The welcome question and feedback text editing intentionally restrict menu activation.

Recovery intentionally does not require the *current* capsule to be clear, a held A button or a walkable route. It still requires valid tracked input/focus, then checks a downward ray against layer-8 floor, slope, finite tracked height and a destination overlap capsule immediately before moving. `CommitRelocation` preserves tracked-head horizontal offset, temporarily disables/re-enables the CharacterController, synchronizes physics, resets movement/teleport state, and emits `Teleported` with `LastRelocationReason=SafetyReset`.

A collider stall alone does not make `ApartmentFurnitureInteractor.RuntimeReady` false, so it should not inherently prevent B opening the menu. This is source-level reasoning, not a headset PASS. Validate while stuck: B still opens; destination is clear; root relocates above floor; locomotion resumes; a held bag does not duplicate or lose grip state; guided progress is retained. Guide exploration distances must reset/ignore the relocation sample, and Entrance completion must check actual arrival rather than merely the reset button.

## Manual inspection checklist before any furniture change

1. Enable Physics Debugger collider display, inspect the named collider's actual shape and active state, and compare mesh bounds in side view.
2. Record floor Y, lowest visible vertex/bounds estimate, lowest solid point and the exact component responsible for obstruction. Preserve a screenshot/log if available; do not invent them.
3. Reproduce with no bag, each bag size, smooth move, A teleport and menu recovery. Distinguish bag warnings from player-body blockage.
4. Propose one object-local adjustment with before/after geometry, bag registry impact and rollback. Obtain explicit permission before applying it.
5. Retest both directions, crouching/head height, cabinet sweep, marker/measurement ray hits and recovery. No all-Y-zero, global floor move or mass collider disabling.
